The I() construct

?formula gives you insights into the way to structure generic formula objects in R. The I() construct is a consistent and clear way in R’s foundations to specify functional operations on variables.

R and GMM

There are a number of packages for estimating GMM models in R. pgmm does many of the most basic models, though Stata is the industry leader in this. That said, there is a relatively new and highly customizable package for this: pdynmc which is described here in a pdf vignette. What follows is a detailed example with a software guide.

Package and command ecosystem

R packages

Install once; load at the top of each script.

install.packages(c(
  "plm",             # core panel estimators: pgmm, pmg, pcdtest
  "panelvar",        # panel VAR with impulse responses
  "lme4",            # mixed models for nonlinear DPD (CRE logit, Poisson)
  "fixest",          # fast FE Poisson and high-dimensional FE
  "marginaleffects", # average partial effects from nonlinear models
  "dplyr",           # data manipulation (also in tidyverse)
  "kableExtra"       # formatted output tables
))
ImportantThe lag() conflict between plm and dplyr

dplyr exports lag() with a scalar-only n argument. plm exports lag() that accepts vector ranges like 1:2, which pgmm() formulas require. Loading both packages without intervention causes:

Error in lag(): ! n must be a whole number, not an integer vector.

Fix: add lag <- plm::lag once after loading both packages. This is done in the hidden setup chunk for this document.

Separate issue: plm::lag applied to a plain numeric vector inside dplyr::mutate() returns the input unchanged — it does not compute a positional lag. Always use dplyr::lag() explicitly in pipeline code:

df |> group_by(id) |> mutate(y_lag = dplyr::lag(y, 1))  # correct
df |> group_by(id) |> mutate(y_lag = lag(y, 1))          # wrong when lag <- plm::lag

Static panel baseline (for comparison)

Always estimate pooled OLS and fixed effects before GMM. They bracket the true \(\gamma\): OLS is upward-biased (omitted \(\alpha_i\)); FE is downward-biased (Nickell). GMM estimates should lie between them.

  • R
  • Stata
# Use precomputed lag columns (n_lag1, n_lag2, w_lag1 from setup).
# Avoids swar_Between_check() failure that occurs when lag <- plm::lag is
# active and lag() appears inside a random-effects formula.

# Pooled OLS (upward-biased gamma)
ols <- plm(n ~ n_lag1 + n_lag2 + w + w_lag1 + k + ys,
           data = pdat, model = "pooling")

# Two-way fixed effects (downward Nickell bias)
fe  <- plm(n ~ n_lag1 + n_lag2 + w + w_lag1 + k + ys,
           data = pdat, model = "within", effect = "twoways")

# Random effects — individual effects only.
# Two-way RE with a lagged DV is numerically fragile (Swamy-Arora
# between-estimator fails when between-transform of lag(n) ≈ between-transform
# of n itself). Individual RE is the sensible baseline comparison.
re  <- plm(n ~ n_lag1 + n_lag2 + w + w_lag1 + k + ys,
           data = pdat, model = "random", effect = "individual")

# Hausman test: FE vs RE
phtest(fe, re)

Anderson-Hsiao: IV estimator

Anderson and Hsiao (1981) first-difference to remove fixed effects, then instrument \(\Delta y_{i,t-1}\) with \(y_{i,t-2}\) (level) or \(\Delta y_{i,t-2}\) (difference). Useful pedagogically as the conceptual predecessor to AB.

  • R
  • Stata
# First-difference by hand.
# MUST use dplyr::lag() explicitly here — plm::lag() on a plain vector
# inside mutate() returns the input unchanged, not a positional lag.
pdat_fd <- EmplUK |>
  group_by(firm) |> arrange(year) |>
  mutate(
    Dn   = n  - dplyr::lag(n, 1),       # Delta y_t
    DLn  = dplyr::lag(n,1) - dplyr::lag(n,2),  # Delta y_{t-1}  (endogenous)
    Dw   = w  - dplyr::lag(w, 1),
    ln2  = dplyr::lag(n, 2),             # y_{t-2}: level instrument
    DLn2 = dplyr::lag(n,2) - dplyr::lag(n,3)   # Delta y_{t-2}: diff instrument
  ) |>
  ungroup() |> filter(!is.na(DLn2))

pdat_fd_p <- pdata.frame(pdat_fd, index = c("firm","year"))

# AH estimator using plm() IV formula syntax: y ~ endog | instruments
# Level instrument y_{t-2}
ah_level <- plm(Dn ~ DLn + Dw | ln2  + Dw, data = pdat_fd_p, model = "pooling")
summary(ah_level)

Arellano-Bond: difference GMM

Arellano and Bond (1991) use all valid lagged levels as GMM instruments. The global lag <- plm::lag (set in the setup chunk) makes pgmm() formulas work correctly throughout.

Formula syntax for pgmm()

Left of |: model covariates with lag structure. Right of |: GMM-type instruments via lag(var, min:max), where 2:99 means all available lags from 2 onward.

One-step Arellano-Bond

  • R
  • Stata
# Replicates Arellano-Bond (1991) Table 4(a1)
# lag() resolves to plm::lag (set globally in setup) -- pgmm formulas work
ab_one <- pgmm(
  log(emp) ~ lag(log(emp), 1:2) +
             lag(log(wage), 0:1) +
             lag(log(capital), 0:2) +
             lag(log(output), 0:2) |
             lag(log(emp), 2:99),
  data   = EmplUK,
  effect = "twoways",
  model  = "onestep"
)

Key cross-software notes

xtabond2 is the recommended Stata command for nearly all GMM DPD work. It supersedes xtabond, xtdpdsys, and xtdpd and is the only command with collapsed instruments, orthogonal deviations, and difference-in-Hansen.

plm::pgmm() is the R workhorse but has three hard gaps: no collapsed instruments, no orthogonal deviations, no difference-in-Hansen. For panels where these matter, call xtabond2 via Stata.

LSDVC and PMG belong to Stata. Bruno (2005) bias-corrected LSDV (xtlsdvc) and Pesaran-Shin-Smith (1999) Pooled Mean Group (xtpmg) have no maintained CRAN implementations.

Slope heterogeneity diagnostics are Stata-favoured. The formal Pesaran-Yamagata \(\tilde\Delta\) test (xtslope) and Dynamic CCE (xtdcce2) have no direct CRAN equivalents. plm::pmg(model = "cmg") provides CCE-MG estimation but without the full DCCE workflow.

Nonlinear DPD is well-handled in both environments via the Wooldridge (2005) CRE approach. lme4::glmer() in R and xtlogit/xtprobit/xtpoisson, re in Stata implement the same estimator. Use marginaleffects::avg_slopes() in R and margins in Stata for average partial effects — always report APEs, not latent-index coefficients.
